# Working Preferences

How the user wants work done. Add to it whenever a preference comes up. The user's newer instructions always win.

## How to work

- **Scope:** only the requested change. No unrequested extras or redesigns.
- **New systems:** start with 3-5 design questions, each with options and a default ("d" = default).
- **Choosing a look:** make 2-3 versions and show them side by side before picking one.
- **Status:** separate what's planned from what's built and what's verified.
- **After each task:** task log, notes, commit and push, remind the user to save in Studio.

## Prompts for another chat

When asked to write a prompt for a new chat, make it stand alone: the goal, notes and files to read first, rules (scope, the server decides anything that matters, no uploads or publishing without asking), how to check the work, and the model and effort. End it with: "What questions do you have for me so I can help you implement this feature as best as possible?"
